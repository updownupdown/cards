# Localization Plan

Status: plan only. The groundwork is scheduled for a future session. It targets English (the source language), French and Spanish, and is built so that more languages can be added later. Translations are generated by AI and checked automatically, with optional human review.

## Goals

- The app follows the phone's language by default and has an in-app language picker (System, English, Français, Español).
- English stays the source of truth. It is edited by hand where it lives today, including the game definitions in `src/data/games/`.
- A translation script drafts and updates the other languages with Claude. It only retranslates text whose English has changed.
- Adding a language means adding its code, a glossary and a store listing, then running the script. No code changes are needed.
- Nothing slows down on native: translations are bundled and loaded synchronously before the first frame.

## What needs translating

These counts were measured on 2026-09-15.

| Area | Where it lives | Size |
| --- | --- | --- |
| Game rules and descriptions | `src/data/games/*.ts`: `title`, `cardDescription`, `quickStart`, `howToPlay` | about 18,900 words across 114 games |
| Game-specific settings | `src/data/game-settings.ts`: labels, options, descriptions | about 1,100 words |
| App UI | `src/app`, `src/components/{Home,Modals,Nodes,common}` | about 200 strings |
| In-game UI | `src/components/Games`: about 130 pile labels, 170 win and loss messages, 80 button labels, and 60 messages built from numbers (for example `` `Restack (${n})` ``) | about 160 distinct strings |
| Quotes | `src/components/Collectibles/QuotesText.ts` | 156 quotes, about 2,600 words (see Decisions) |
| Tao Te Ching | `src/components/Collectibles/TaoText.ts` | 81 chapters, about 8,200 words (see Decisions) |

| Store | Play and App Store listings, and the tagline in `scripts/generate-store-graphics.mjs` | per store |

That is roughly 24,000 words without the collectibles and 35,000 with them. At that size, API cost is low per language.

## Decisions to make before the groundwork session

1. **Game titles.**
   - Recommendation: translate classic patience names that have well-known local names, such as Spider (Araignée / Araña), Pyramid (Pyramide / Pirámide) and Clock (Horloge / Reloj).
   - Keep invented or renamed game names as brand names unless they are plain descriptive words.
   - Check translated names against trademarks, as was done for English.
   - Search matches both the localized and the English name.
2. **Quotes.**
   - Most quotes were written in English. Epictetus, Marcus Aurelius and Seneca appear in public-domain English translations.
   - Recommendation: show a translated quote with a "Show original" option, and keep the author and source unchanged.
   - Alternative: keep quotes in English for every language.
3. **Tao Te Ching.**
   - The current text is John H. McDonald's English translation. AI-translating it creates a derivative, so first confirm his licence allows that.
   - Options:
     - AI-translate McDonald's text, after the licence check (recommended if the licence allows);
     - use public-domain French and Spanish translations, whose style is older and uneven;
     - keep English for the first release.
4. **Formality.**
   - Recommendation: use "vous" in French.
   - For Spanish, use neutral international Spanish with "tú".
5. **Card faces.**
   - The card images show English indices (A, K, Q, J), while French decks use R, D, V.
   - Recommendation: keep the card art unchanged, and translate rank and suit names only in text.
6. **Human review.**
   - Recommendation: have a native speaker check at least the store listing, the quick start text, and the rules of about ten popular games in each language.
   - Everything else ships with AI review only.

## Architecture

### Libraries

- **`expo-localization`** provides the device language list through `getLocales()`, and on web too.
  - Its config plugin option `supportedLocales` generates Android's `locales_config.xml`, which enables per-app language in Android 13+ system settings. It also adds a `resourceConfigurations` entry that drops unused library translations from the APK.
  - On iOS it sets `CFBundleLocalizations`.
  - Android can change language while the app runs, so check it again when the app returns to the foreground (`AppState`). This behaviour is documented in the SDK 55 docs.
- **`i18next` and `react-i18next`** handle interpolation, plurals, fallback to English and namespaces, and can type-check keys.
  - Initialize them synchronously with bundled resources. Don't use an async backend.
- **A plural rules polyfill** is needed: `intl-pluralrules`, or FormatJS's `@formatjs/intl-pluralrules` with only en, fr and es data.
  - Hermes has no `Intl.PluralRules`, which i18next relies on.
  - Hermes does support `Intl.NumberFormat`, `Intl.DateTimeFormat` and `Intl.Collator`, which cover number formatting and sorting.
- Lingui was considered as an alternative. It extracts strings at compile time, but adds a Babel macro alongside the React Compiler and has no clear advantage for an AI translation workflow built on JSON files.

### Where strings live

- **UI strings** move into `src/locales/en/<namespace>.json`, which is edited by hand. Suggested namespaces are `common`, `home`, `nodes`, `settings`, `modals` and `cards`. Code reads them with `t("home.gameOfTheDay")`.
- **Content** stays in English in the existing TypeScript files, so the game definitions keep their current structure.
  - An extraction script writes `src/locales/en/games.json` and `settings.json` from them. These are generated files, not edited by hand.
  - The script keys them by game path and field, for example `klondike.howToPlay`, and stores a hash of the English source for each field.
- **Translations** live in `src/locales/<lang>/*.json`. Each field records the hash of the English it was translated from.
  - When the English changes, the translation is stale and the app shows English for that field until the script runs again. That way, outdated rules text is never shown.
  - A test lists stale fields, so they are caught before release.
- **At runtime**, `getLocalizedGame(game)` and `useGameText(path)` lay translated fields over the English definition, field by field, falling back to English.
- **In-game strings** go through the minimum change inside each game component:
  - pile labels such as `text: t("cards.stock")`;
  - win and loss messages, and button labels such as `t("cards.redeal", { count })`.
  - Terms used across games (Stock, Waste, Foundation, Reserve, Tableau, Draw, Redeal) share keys in `cards`. Game-specific text goes under `games.<slug>`.
  - Add `t` to the dependencies of the `useMemo` calls that build zones.
  - Pure helper functions that return messages use the global `i18next.t`.

### Formatting, sorting and search

- **Numbers and percentages** (win rate, scores): use `Intl.NumberFormat` for the active language.
- **Plurals:** use i18next's `_one` and `_other` keys. French treats 0 as singular.
- **Sorting by title:** `useHomeData`, `StatsTab`, `GamesCollectionModal` and `card-back-colors` sort with `localeCompare`. Pass the active language to it.
- **Search** in `SearchTab`:
  - match the localized title, the English title and the aliases;
  - ignore accents by normalizing to NFD and stripping combining marks.

### Layout

- French and Spanish run about 15–30% longer than English. Places likely to overflow:
  - the tab bar;
  - in-game button labels such as `"Search\n(Draw 2)"`;
  - the rotate hint;
  - the node details panel;
  - settings rows;
  - modal titles.
- Pile labels already shrink their text to fit, so they need no extra work.
- A dev-only pseudo-locale lengthens every string by 40% and adds accents, for example `[Ŝţöçķ ~~~]`. It catches overflow and missed hardcoded strings before any real translation exists.
- The Outfit font has every French and Spanish accented letter, plus `« » ¿ ¡ ’`. Before use, check that it also has the narrow no-break space French puts before `; : ! ?`, or skip that typographic convention.

### Native, store and web

- **App config:** add `["expo-localization", { supportedLocales: ["en", "fr", "es"] }]` to `app.config.js`, then prebuild again. `android/` is gitignored, so re-apply the local `applicationIdSuffix` edits in `android/app/build.gradle` afterwards.
- **App name:** SoloSuite in every language.
- **Stores:** add localized listings in Play Console and App Store Connect. Give `scripts/generate-store-graphics.mjs` a `--lang` option for the tagline.
- **Web:** static export renders English HTML. Set `document.documentElement.lang` when the language resolves, and accept a brief English first paint for now.

## AI translation pipeline

`scripts/translate.mjs` runs locally and never ships in the app.

- **Input:** English JSON, a per-language glossary (`src/locales/glossary.<lang>.json`) and a shared style guide.
  - The glossary covers solitaire terms (for example foundation: fondation / fundación; waste: défausse / descarte; free cell: cellule libre / celda libre), suit and rank names, and the agreed game titles.
- **Change detection:** only keys that are new or have a changed source hash are sent.
- **Model:** `claude-opus-5` for rules text and the review pass, and `claude-sonnet-5` for short UI strings. Requests are batched with JSON output.
- **Context sent with each key:** where it appears, a length hint, whether it contains markdown, and its placeholders.
- **Automatic checks after each batch:**
  - the same keys come back;
  - placeholders such as `{{count}}` are preserved;
  - markdown markers (`**`, `##`, `- `) match the source;
  - no English is left untranslated;
  - suspicious length changes get a warning.
- **Review pass:**
  - a second request checks each translation against the glossary and, for rules, against the English meaning;
  - it writes an issues report for the rules of any game that fails a check;
  - the flagged translations are sent again.
- **Usage:** the Anthropic API key lives in `.env.local` (gitignored). `--dry-run` prints the word count and number of requests before spending anything.
- **Output:** results are committed like any other change and reviewed as a git diff.

The following tests run on every build:
- every language has every key, or falls back to English;
- placeholders and markdown match the English;
- no field is stale;
- the random-play game test also passes in French.

## Groundwork session steps

1. **Infrastructure, with no visible change:**
   - install `expo-localization`, `i18next`, `react-i18next` and the plural rules polyfill (check versions against React 19 and React Native 0.83);
   - add `src/i18n/` with synchronous init, `SUPPORTED_LANGUAGES` and language resolution;
   - add a `language` global setting (`"system" | "en" | "fr" | "es"`) with normalization in `game-menu.ts`;
   - check the language again when the app returns to the foreground;
   - add typed keys;
   - add the pseudo-locale;
   - make Jest use English.
2. **App shell strings:**
   - move Home, Nodes, the modals, the common components and the privacy page onto keys;
   - add the Settings language picker;
   - add `eslint-plugin-i18next`'s `no-literal-string` rule as a warning for `src/app` and `src/components`.
3. **Content layer:**
   - add the extraction script for game definitions and settings;
   - add `getLocalizedGame` and `useGameText`;
   - switch everything that reads game text to the localized fields: HomeCard, GameModal, RulesModal, TipsBox, SearchTab, StatsTab and NodeDetailsPanel.
4. **In-game strings:** convert the shared boards first (StockTableauSolitaire, FanSolitaire, SingleDeckSpider, WastePilesSolitaire, RowsSolitaire), then the rest in batches, keeping each file's structure.
5. **Translation:** add the pipeline, glossaries and checks, generate French and Spanish, and review the diffs.
6. **QA:**
   - run the all-games phone sweep in the pseudo-locale, French and Spanish, and fix overflow;
   - run the random-play test in French.
7. **Release:** add the `supportedLocales` config and rebuild, the store listings, the localized store graphics and the translated privacy policy.

Steps 1–3 fit in one session. Steps 4–6 take one or two more.

## Later languages

- **German:** long compound words, so test with the pseudo-locale expansion.
- **Right-to-left (Arabic, Hebrew):** the card layouts are positioned absolutely, so keep `supportsRTL` off, and design mirrored layouts deliberately.
- **Chinese, Japanese, Korean:** Outfit has no CJK glyphs, so add a fallback font.
